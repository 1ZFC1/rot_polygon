# rot_polygon · 旋转多边形生成器

生成一个**绕中心旋转的正 n 边形 / 矩形**的引导线谱面：n 个顶点各占一个画布，边用跨画布
的线连起来。参数从命令行给，也可以直接运行进入「黑框问答」。

```
python rot_polygon.py                            # 交互式（会解释单位）
python rot_polygon.py --sides 4 --radius 2       # 正方形，外接圆半径 2
python rot_polygon.py --sides 6 --radius 1.5     # 正六边形
python rot_polygon.py --sides 4 --width 3 --height 2
python rot_polygon.py --sides 4 --radius 2 --into chart.json   # 追加到已有谱面（接在末尾）
python rot_polygon.py --into chart.json --canvas-start 70      # 从第 70 个画布开始（自动补空画布）
```

![四联帧：tick 8 / 36 / 64 / 92](example_frames.png)

## 生成方式：全程走库里，不手写 JSON

```python
chart = rcf.new(bpm)                                   # 主题/挑战时间等由库建
rcf.addCanvas(chart) / rcf.addCanvasPosition(...) / rcf.addCanvasSpeed(...)
rcf.addLine(chart, [节点, 节点], {"time":0, "startColor":…, "endColor":…})
rcf.export(chart, 路径)                                 # 库自己写文件
```

所以输出结构和编辑器保存的谱面一致（主题 `colorsList`、线节点带 `color`、节点 `floorPosition`
由库按画布地板计算）。

## 几何：顶点钉在画布上

n 个画布沿同一个外接圆运动、相位相差 `360°/n`：

```
x_k(t) = cx + R·cos(θ(t) + φ_k)     → 画布的 xPosition 关键点
y_k(t) = cy + R·sin(θ(t) + φ_k)     → 画布的流速（世界 y = S1 × floorPosition）
θ(t)  = θ0 + 2π·(t − start) / rev          rev = 转一圈的拍数
```

* **顶点**：每个画布原点上一个点（`xPosition = 0`），画布动它跟着动；
* **边**：一条线两个节点在同一时刻、分别挂在相邻两个画布上；
* 一份正方形谱面只有 **8 条线**（4 点 + 4 边）。

库的 floor 模型是「`fp(t) = 关键点 fp + 关键点速度 × 秒差`」（段内速度恒定），所以程序给每个
关键点填的是**到下一个采样点的平均速度**——这样每个采样点都严格落在正弦上（实测几何误差
`1e-15`，内角误差 `0.0000°`）。

矩形（宽≠高）的四角在圆上**不等距**（相邻圆心角 = `180° − 2·atan(H/W)`），程序已按此处理。

## 尺寸标准（都在这几个单位里）

```text
世界单位          ：长度/高度的统一单位。一屏高 = 6.9 世界单位，一屏宽 = 5.625
xPosition 单位    ：画布横向坐标的单位。1 xPosition = 5.625 世界单位
拍（tick）        ：时间单位。320 BPM 时 1 拍 = 0.1875 秒
半径 R            ：外接圆半径（世界单位）——顶点到圆心的距离
边长              ：正 n 边形 = 2R·sin(π/n)；矩形 = 宽/高
圆心高度 center_y ：世界单位，判定线是 0；安全区间大约 0.8 … 5.5（一屏 0…6.9）
```

换算例子：

| 半径 R | 边长（正方形） | 直径占一屏 | 圆心放 3.2 时 y 范围 |
| --- | --- | --- | --- |
| 1.0 | 1.414 | 29% | 2.2 – 4.2 |
| 2.0（默认） | 2.828 | 58% | 1.2 – 5.2 |
| 3.0 | 4.243 | 87% | 0.2 – 6.2（快出屏） |

## 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--sides` | 4 | 边数（≥3） |
| `--radius` | 2 | **外接圆半径**（世界单位；一屏高 = 6.9） |
| `--side` | — | 按边长给（正多边形），与 `--radius` 二选一 |
| `--width` / `--height` | — | 矩形宽高（仅 `--sides 4`，优先于 `--side`） |
| `--radius` | — | 直接给外接圆半径 |
| `--flow` | 7.5 | 编辑器「播放流速」 |
| `--bpm` | 320 | BPM（`--into` 时取目标谱面的） |
| `--start` / `--end` | 8 / 92 | 起始拍 / 结束拍 |
| `--rev` | 0 | 旋转一圈要几拍（0 = 整段正好转一圈） |
| `--step` | 0.5 | **采样间隔（拍）**：越小越顺滑、关键点越多（320 BPM 下 0.5 拍 = 0.094 秒） |
| `--phase` | 0 | 初始角度（度） |
| `--center-x` | 0 | 中心 x（xPosition 单位） |
| `--center-y` | 3.2 | 圆心高度（世界单位；一屏 = 6.9，默认约半屏） |
| `--canvas-base` | 1 | 顶点从第几个画布开始编号（0 号补位） |
| `--park` | 0 | 正弦段之后、1 流速段之前的静止长度（tick） |
| `--lift-ticks` | 自动 | 1 流速段的长度；默认由 `--center-y` 反算 |
| `--post-speed` / `--post-ticks` | 0 / 0 | 结束拍之后的流速与延续拍数 |
| `--colors` | 内置 8 色 | 顶点调色板，如 `"#ff0000,#00ff00,#0000ff,#ffff00"`（循环使用） |
| `--color` | — | 所有顶点/边统一颜色，如 `"#ffffff"`（覆盖调色板） |
| `--no-edges` / `--no-dots` | 关 | 不要边 / 不要顶点 |
| `--into` | — | 追加到已有谱面（原内容不动，新画布接在末尾） |
| `--canvas-start` | 末尾 | 追加时从第几个画布开始；会自动补空画布，且不能小于现有画布数 |
| `--stagger` | 0.25 | 相邻顶点挂靠拍错开的拍数（0 = 同一拍；错开后在编辑器里能分别选中） |
| `--hold` | 2.0 | 抬升之后静止的拍数；错开的挂靠点落在这段里，才不会被错开带歪 |
| `--out` | `rot_polygon_chart.json` | 输出文件 |
| `--verify` | 关 | 生成后校验几何并回读 |
| `--interactive` | 关 | 无参数运行时也进问答式 |

## 追加到现有谱面

```powershell
python rot_polygon.py --sides 4 --radius 2        # 正方形，半径 2
```

原有画布与线保持不变（已验证），新顶点画布接在末尾，边指向这些新画布。

## 注意

* 只有几何，**没有出场/后续动作**，按你的习惯自己接。
* 谱面库由工具自动定位（`../rizChartFunction_Library/src`），也可用 `RIZCHARTFUNCTION_SRC` 指定。

## 颜色

* `--colors "#ff0000,#00ff00,#0000ff,#ffff00"`：按顶点顺序取色，不够就循环；
* `--color "#ffffff"`：所有顶点和边统一一个颜色；
* 边的两个端点**各用自己顶点的颜色**（红→绿、绿→蓝…），编辑器会自动在相邻不同颜色
  的节点之间做渐变——想要整条边纯色，就用 `--color` 或让相邻顶点同色；
* 颜色写法：`#rrggbb`、`#rgb`、`"r,g,b"` 都行；多个调色板项用逗号分隔（含 `#` 时）
  或分号分隔（写 `r,g,b` 列表时）。

## 节点错开（方便在编辑器里选中）

原来四个顶点都在同一拍，编辑器里叠在一起没法单独选。现在按参考谱面的做法：

```text
顶点 k 的挂靠拍 = 画线拍 + k × stagger（默认 0.25 拍）
边的两个端点 = 各自顶点的挂靠拍（所以一条边的两个节点也在不同拍）
```

实测（正方形，画线拍 94.148）：

```text
点线：94.148 / 94.398 / 94.648 / 94.898
边  ：(1,2)=94.148→94.398  (2,3)=94.398→94.648  (3,4)=94.648→94.898  (4,1)=94.148→94.898
```

**为什么不会变形**：错开的挂靠点必须落在「流速 0 的静止段」里（`--hold`，默认抬升后 2 拍）。
静止段里各画布的 floorPosition 相同，所以错开只改节点所在拍、不改高度——
`--verify` 仍是边长误差 1e-3、内角 0.04°。

## 关键点与缓动

* **x（水平）：统一密集线性（ease 0）**，`--step`（默认 0.5 拍）控制密度；320 BPM 下 0.5 拍 ≈ 0.094 秒，弦误差约 4e-4 世界单位。
  曾试过「四分点 + ease 17/18」，正方形能精确拟合，但 n≠4 时顶点相位不是 90° 的整数倍、
  四分点对不齐窗口边界，各形状不统一，故统一退回线性。
* **y（垂直）**：`speedKeyPoints` 按「到下一采样点的平均速度」拟合（库的模型是段内速度恒定），
  落点严格在目标曲线上。
